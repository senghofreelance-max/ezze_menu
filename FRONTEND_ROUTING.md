# Single-Domain Frontend Routing in Frappe

This document explains how to serve multiple Vue SPAs under one Frappe domain without separate domains or subdomains.

## Architecture Overview

```
domain.com/desk         → Frappe Desk (built-in)
domain.com/menu-admin   → ezze_menu_admin Vue SPA (admin operations)
domain.com/order-app    → ezze_menu_order_app Vue SPA (user ordering)
```

All three share the same domain. Frappe serves the SPA HTML shells; the browser loads JS/CSS from `/assets/`.

---

## How It Works

### 1. Frappe Static Asset Path

Frappe serves `apps/<app>/public/` at `/assets/<app_name>/`:

```
apps/ezze_menu/ezze_menu/public/menu_admin/  →  /assets/ezze_menu/menu_admin/
apps/ezze_menu/ezze_menu/public/order_app/   →  /assets/ezze_menu/order_app/
```

**The Vite `base` must match this path exactly.** This ensures the generated HTML `<script>`/`<link>` tags AND the CSS `@font-face` `url()` references all point to the correct location. If `base` doesn't match, fonts and other CSS-referenced assets will 404.

### 2. Frappe WWW Pages

Files in `apps/<app>/ezze_menu/www/` become web pages:

```
www/menu-admin.html + www/menu_admin.py  →  domain.com/menu-admin
www/order-app.html  + www/order-app.py  →  domain.com/order-app
```

The `.py` file sets context (no_cache, no sidebar, boot data).

### 3. SPA Sub-Route Handling (hooks.py)

Vue Router handles client-side navigation (e.g., `/menu-admin/settings`). Frappe must return the SPA shell for all those paths. Add `website_route_rules` in `hooks.py`:

```python
# apps/ezze_menu/ezze_menu/hooks.py
website_route_rules = [
    {"from_route": "/menu-admin", "to_route": "/menu-admin"},
    {"from_route": "/menu-admin/<path:dashboard>", "to_route": "/menu-admin"},
    {"from_route": "/order-app", "to_route": "/order-app"},
    {"from_route": "/order-app/<path:page>", "to_route": "/order-app"},
]
```

### 4. Vite Dev Mode Proxy

`vite.base.js` proxies `/assets/` to Frappe so the dev server can load other apps' assets. But it must NOT proxy the current app's own assets — those are served by the Vite dev server itself (for HMR). This is handled automatically via a `bypass` function in `getProxyOptions(base)` that checks if the request is for the current app's asset prefix and bypasses the proxy if so.

## File Structure for Each SPA

```
apps/ezze_menu/
├── ezze_menu/
│   ├── hooks.py                    ← website_route_rules
│   ├── public/
│   │   ├── menu_admin/             ← Vite build output (JS/CSS/fonts)
│   │   └── order_app/             ← Vite build output
│   └── www/
│       ├── menu-admin.html         ← HTML shell (auto-generated by build)
│       ├── menu_admin.py           ← Frappe page context
│       ├── order-app.html          ← HTML shell (auto-generated by build)
│       └── order-app.py            ← Frappe page context
├── ezze_menu_admin/
│   ├── vite.config.js              ← base: "/assets/ezze_menu/menu_admin/"
│   └── package.json                ← build script
├── ezze_menu_order_app/
│   ├── vite.config.js              ← base: "/assets/ezze_menu/order_app/"
│   └── package.json                ← build script
└── frontend/shared/
    ├── vite.base.js                ← shared Vite config factory (with smart proxy bypass)
    └── scripts/sync-html.mjs      ← copies Vite HTML to www/
```

## Adding a New SPA Frontend

Follow these steps to add another Vue SPA (e.g., `kitchen-display`) at `domain.com/kitchen`.

### Step 1 — Configure vite.config.js

```js
// apps/ezze_menu/ezze_menu_kitchen/vite.config.js
import path from "path";
import { fileURLToPath } from "url";
import { createSharedViteConfig } from "../frontend/shared/vite.base";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export default createSharedViteConfig({
    appDir: __dirname,
    base: "/assets/ezze_menu/kitchen/",        // ← MUST match Frappe asset path
    outDir: path.resolve(__dirname, "../ezze_menu/public/kitchen"),
    port: 8085,                                // ← unique dev port
});
```

> **Rule:** `base` = `/assets/<frappe_app_name>/<public_subfolder>/`
> where `public_subfolder` matches the `outDir` folder name inside `public/`.

### Step 2 — Configure package.json build script

```json
{
  "scripts": {
    "dev": "vite --port 8085",
    "build": "vite build && node ../frontend/shared/scripts/sync-html.mjs ../ezze_menu/public/kitchen/index.html ../ezze_menu/www/kitchen.html"
  }
}
```

### Step 3 — Create www context file

**`apps/ezze_menu/ezze_menu/www/kitchen.py`**:
```python
import frappe

def get_context(context):
    context.no_cache = 1
    context.show_sidebar = False
    context.title = "Kitchen Display"
    context.boot = frappe._dict()
```

The `kitchen.html` will be auto-generated by `npm run build`.

### Step 4 — Add route rules to hooks.py

```python
# apps/ezze_menu/ezze_menu/hooks.py
website_route_rules = [
    # ... existing rules ...
    {"from_route": "/kitchen", "to_route": "/kitchen"},
    {"from_route": "/kitchen/<path:page>", "to_route": "/kitchen"},
]
```

### Step 5 — Build and deploy

```bash
# Build the SPA
cd apps/ezze_menu/ezze_menu_kitchen
npm install
npm run build

# Sync assets to sites/assets/ezze_menu/
cd /path/to/dev-bench
bench build --app ezze_menu

# Reload Python (required after hooks.py changes)
bench restart
```

## Development (with HMR)

```bash
cd apps/ezze_menu/ezze_menu_admin
npm run dev     # starts on port 8087, access via http://localhost:8087
```

The dev proxy automatically bypasses Frappe for `/assets/ezze_menu/` paths so the Vite dev server serves its own assets (enabling HMR). All other paths (`/api`, `/login`, `/app`, other `/assets/`) are proxied to Frappe.

## Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Vite `base` doesn't match Frappe asset path | CSS `@font-face` icons show as empty squares; JS/CSS 404 | Set `base: "/assets/<app>/<folder>/"` |
| Forgot `bench build --app <app>` | Assets work in Vite dev but 404 through Frappe | Run `bench build` after `npm run build` |
| Forgot `bench restart` after `hooks.py` change | Sub-routes return 404 | Run `bench restart` |
| `www/<slug>.html` filename doesn't match `to_route` | Route rule has no effect | Filename `<slug>.html` → served at `/<slug>` → `to_route: "/<slug>"` |
